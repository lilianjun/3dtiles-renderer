# ADR-0013: PBR material pipeline — status, the missing texture provider, and verification (P15)

## Status

Accepted (2026-09-29).

## Context

P2–P14 proved geometry reaches the screen, but every fixture used flat
`baseColorFactor`-only materials. The project plan requires "glTF/GLB base
PBR: color, metallic/roughness, normals, transparency/double-sided", and an
SDK whose PBR path was never exercised is incomplete. P15 set out to verify
the pipeline with experiments, not assumptions.

## Investigation: what was actually in the scene

Reading `src/renderer.cpp` and `src/tileset.cpp` before touching anything:

- The scene **does** contain a light: a `DIRECTIONAL` sun (color
  ~warm white, intensity 100000 lux, direction (0,−1, 0.35)), added in P3
  explicitly "so PBR glTF tile content is lit". It does not affect the P2
  `unlit` demo triangle.
- Tile content goes through `gltfio::AssetLoader` +
  `createUbershaderProvider(UBERARCHIVE_DEFAULT_DATA)` — Filament's full
  lit PBR ubershader. The black sides / lit tops in the P7/P9 screenshots
  are single-directional-light Lambert shading (no IBL, no ambient), not a
  bug.
- There is **no** image-based lighting / environment map. Consequence for
  verification (not a defect): metals can only show the sun's specular
  lobe; a mirror-smooth metal with nothing to reflect renders black.

## The real gap found: no texture provider

The first P15 fixtures with **embedded PNG textures** (checkerboard
`baseColorTexture`, hand-made `normalTexture`) rendered **black**, and the
demo logged:

```
Missing texture provider for image/png
```

Root cause: gltfio's `ResourceLoader` decodes images through a
client-supplied `TextureProvider`; `FilamentPrepareResources` never
registered one, so every textured material silently lost its textures.
Why it went unnoticed: no fixture before P15 used any texture — all P2–P14
materials were factor-only.

## Decision

Wire Filament's prebuilt stb decoder into the render bridge (no third-party
source changes):

- `src/tileset.cpp`: `FilamentPrepareResources` now creates
  `gltfio::createStbProvider(engine)` and registers it for
  `image/png` + `image/jpeg` on the `ResourceLoader`; destroyed (after the
  `ResourceLoader`) in the destructor. Guarded by
  `TILES_WITH_STB_PROVIDER`.
- `CMakeLists.txt`: appends `stb` to the Filament prebuilt lib list **only
  if** `libstb.a` exists in the downloaded package (checked per platform
  layout, incl. the iOS xcframework path), and defines
  `TILES_WITH_STB_PROVIDER` then. Otherwise a configure-time warning is
  emitted and behavior is unchanged (textures still won't decode there).
- No new default light was needed: the P3 sun is sufficient and PBR was
  already lit. No IBL was added — the no-environment look (dark metals) is
  honest and documented; adding a fake environment would change every
  golden screenshot.

## Verification (all on Linux/Mesa + xvfb, deterministic fixtures in
`tests/data/p15_*`, generated by `tests/data/gen_p15_pbr_tileset.py`)

| Feature | Result |
|---|---|
| metallic 0 vs 1 (same base color) | metal mean luminance 5.6 vs dielectric 15.1; region color distance 16.5 — significant and metal-typical (no diffuse without IBL) |
| roughness 0.08 vs 0.9 (metal) | smooth metal ~black (mirror, nothing to reflect, max 0); rough metal shows broad sun sheen (mean 18.6, max 95) |
| normal map vs flat | shading differs (region color distance 6.5, peak 134 vs 117); stipple visible on screenshots |
| alphaMode BLEND vs OPAQUE | 19062 px differ; lit top-face red 186.6 → 102.9 (between opaque red and dark interior); interior faces revealed (mid-red px 2994 → 7266) |
| single vs double-sided (plane facing away) | single-sided: 0 non-background px (fully culled); double-sided: 9757 px visible |
| checkerboard baseColor texture | both tones sampled (1078 bright + 17487 dark px in box region) |

Assertions are region/render comparisons and sane-range checks — no
hard-coded Mesa shading values. `tests/pbr_test.py` is registered as
`pbr_materials_screenshot`; the checkerboard fixture also runs under
ASan/LSan/UBSan as `sanitizer_pbr`.

## Consequences / known limits

- Textured glTF now works on every platform whose Filament package ships
  `libstb.a` (verified present on Linux; other platforms resolve at their
  configure time with a loud warning otherwise).
- KTX2/BasisU textures are not wired (`createKtx2Provider` exists but no
  fixture/decoder was validated) — out of scope, documented here.
- No IBL: metals look dark except for the sun glint. If product visuals
  later need richer metals, add an IBL environment (and re-freeze goldens).
- `EXT_mesh_gpu_instancing` remains CPU-expanded (ADR-0008); unrelated.
